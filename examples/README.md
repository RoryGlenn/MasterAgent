# Checked-in Examples

These files are synthetic, credential-free documentation fixtures. UUIDs,
timestamps, and run IDs are snapshots; capability names, schemas, safety
states, and command behavior must match the current release.

- `weekly-status-plan.json`, `weekly-status-live-plan.json`, and
  `communication-context-live-plan.json` use the current `ChangePlan@2.0`
  schema.
- `inspect-output.txt` is an abbreviated human-readable excerpt; the CLI also
  prints each complete action JSON object.
- `apply-output.txt` records the expected rejection of a legacy unbound apply.
  A successful applied run requires the manifest-binding and exact-approval
  workflow documented in the root README.
- `phase2-demo/` and `phase2b-demo/` contain synthetic rendered packages
  generated by the adjacent `generate_*.py` scripts.
- `v1-demo/` is an integrity-manifested local draft demonstration. Nothing in
  it was sent, uploaded, committed, or published.

Run `python3 scripts/validate_release.py` to verify example plan schemas, local
links, safe defaults, and the v1 demonstration manifest.
