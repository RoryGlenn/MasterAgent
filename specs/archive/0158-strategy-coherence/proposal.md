# Proposal

## Problem

The systems gate proves that a non-trivial assessment and strategy kernel are
complete, immutable, and structurally traced to every plan action. It does not
require explicit evidence that the strategy diagnosis addresses the assessed
constraint, that the guiding policy targets the leverage point, or that the
objective and intended effects support the desired outcome and success metric.
Independent, well-formed checklists can therefore disagree without detection.

The development contracts also need an explicit handoff: outcome ownership and
capability-gap implementation must remain inside the admitted strategy scope,
and documentation maintenance must review the same outcome and tradeoffs.

## Desired outcome

Every gated plan carries one immutable, fingerprint-bound coherence review from
an explicit trusted planning boundary. False, missing, malformed, mismatched,
stale, or forged findings fail closed. The force-multiplier and documentation
contracts consume the same strategic scope without adding another agent or
authority mechanism.

## Scope

Add a typed strategy-coherence review and evidence-backed reviewer, enforce the
review in the existing systems gate, bind static registered interventions at
their explicit code-owned boundary, and update the force-multiplier, Docs Agent,
architecture, developer guide, behavioral requirements, semantic route, and
focused validation.

## Rationale

Explicit attestations make each semantic handoff reviewable and immutable while
remaining honest about the deterministic runtime boundary: MasterAgent can
validate who supplied the findings and exactly what they cover, but it must not
pretend that token overlap or generated prose proves good strategy.

## Alternatives considered

- Token-overlap or keyword matching is brittle, gameable, and not semantic
  validation.
- A separate strategy or philosophy agent would add complexity and another
  bypassable handoff.
- Documentation-only guidance would leave runtime plans structurally valid even
  when the coherence review was omitted.

## Non-goals

The runtime will not infer semantic agreement, call a model to judge strategy,
grant authority from coherence evidence, or require strategy evidence on the
existing low-risk fast path.

## Risks

Existing gated serialized plans lack the new review and must be replanned.
Static registered workflows remain concise because their binder is the explicit
code-owned review boundary. Public fingerprints cannot authenticate a reviewer,
so a deserialized gated plan needs authenticated whole-plan review before
applied execution. Incorrect positive findings from a trusted boundary remain a
trusted-input failure, so documentation must state that the review is an
attestation, not a semantic theorem.
